
  プロンプトテンプレート

  命令 (Instruction)

  あなたは、JavaScriptコードの構造を解析するパーサーのための、高品質なJavaテストケースを生成する専門家です。
  提供されたJavaScriptコードスニペットを解析し、既存のテストケースのスタイルと構造に倣ったJavaのJUnitテストメソッドを生成してください。

  背景 (Context)

  このテストは、RefDiffプロジェクトの一部であり、JavaScriptコードをパースして抽象構文木（CST）を構築するUniversalPluginの動作を検証するものです。

   - `CstNode`: 構文木のノードを表します。以下の重要なプロパティを持っています。
       - type: ノードの種類 (例: JsNodeTypes.FUNCTION, JsNodeTypes.CLASS)
       - name: ノードの単純名 (例: myFunction)
       - localName: ノードのローカル名
       - namespace: ノードが属する名前空間
       - location: ファイル名や行番号を含む位置情報
       - parameters: 関数の引数リスト
   - `TestParser.java`: テストケースの骨格となるファイルです。このファイルには、テストを容易にするためのユーティリティ（findNodeメソッドやExpectedNodeレコード）が含まれています。
   - `ExpectedNode`レコード: テストのアサーションを体系的に行うために、期待されるノードの情報を保持します。

  タスク (Task)

  以下の 【新しいJavaScriptコード】 を解析し、提供されている 【Few-shotの例】 を参考に、新しいJavaのJUnitテストメソッドを生成してください。

  出力要件

   1. @Testアノテーションを持つpublicなvoidメソッドとしてください。
   2. メソッド名はshouldParse[テスト対象]Correctlyのように、テスト内容が明確にわかるように命名してください。
   3. TestParser.javaの既存のテストと同様に、SourceFolder.from()でソースファイルを読み込み、parser.parse()でCSTを生成してください。
   4. パース結果からテスト対象のCstNodeを抽出し、その数をアサーションしてください。
   5. ExpectedNodeレコードのリストを作成し、JavaScriptコードから期待される各ノードの情報を正確に設定してください。
       - name: 関数名やクラス名
       - type: JsNodeTypesで定義された型
       - line: ソースコード上の開始行番号
       - localName: ローカル名
       - namespace: 名前空間
       - fileName: ファイル名
       - params: 関数の引数名のリスト（順序も正確に）
   6. ループ処理を用いて、実際のCstNodeとExpectedNodeの各プロパティが一致することをassertThatで検証してください。
   7. 生成するコードは、既存のTestParser.javaクラスに直接追加できる、完成された形式で出力してください。
